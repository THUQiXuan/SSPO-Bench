## 1. 问题定义与研究背景（Problem Formulation）

### 1.1 为什么优化 `Pass@1` 或 `Pass@K` 不等于优化实际部署性能？

在算法竞赛编程（Competitive Programming）和代码生成任务中，给定一道编程题 $x$，模型会生成一段 Python 程序 $y \sim \pi_\theta(\cdot \mid x)$。每道题目包含两类测试数据：
1. **公开样例测试（Public Examples）**：题目描述中直接给出的少量输入输出样例（通常 1～3 组），在推理/部署时**可见**，模型或外部脚本可以自由运行程序来检查是否通过公开样例。
2. **隐藏测试集（Hidden Tests）**：评测系统私有的完备测试数据（包含边界条件、大压力测试等），仅在**训练阶段的奖励计算**和**最终评测打分**时由裁判系统使用，**在测试时挑选阶段完全不可见**。

在实际部署代码大模型时，人们通常不会只采样 1 个程序直接提交（即 `Pass@1`），也不会拥有一个能偷看隐藏测试集的“神谕（Oracle）”从 $K$ 个候选程序里挑出正确程序（即理论上限 `Pass@K`）。真实的测试时扩展（Test-Time Scaling）流程是：
- 对每道题 $x$，从策略 $\pi_\theta(\cdot \mid x)$ 独立采样 $K$ 个候选程序 $Y_K = (y_1, \dots, y_K)$（本基准中标准部署预算为 $K = 8$）；
- 通过一个仅依赖公开样例与执行行为的**确定性挑选器（Selector）$\mathcal{S}(Y_K)$**，从 $K$ 个候选中选出**唯一一个**程序 $\hat{y} = \mathcal{S}(Y_K)$ 进行最终提交；
- 用隐藏测试集检验 $\hat{y}$ 是否完全正确（$g(\hat{y}) \in \{0, 1\}$）。

### 1.2 测试时挑选器 $\mathcal{S}(Y_K)$ 的两阶段机制

对于任意候选程序 $y_i$，我们在题目公开样例输入及探针输入（Probe Inputs）上运行它（超时限制 `1.5s`，内存限制 `2 GB`），得到两个测试时可观测信号：
1. **公开样例通过指示 $\text{Chk}(y_i) \in \{0, 1\}$**：当且仅当 $y_i$ 在所有公开样例上均未超时/报错且输出与公开样例标准答案一致时，$\text{Chk}(y_i) = 1$；否则 $\text{Chk}(y_i) = 0$。
2. **规范化输出签名（Execution Output Signature）$\sigma(y_i) \in \Sigma^*$**：将 $y_i$ 在各测试输入上的标准输出（去除首尾空白符与行尾空格）拼接为唯一字符串签名；若发生超时则记为 `"TLE"`，若运行崩溃或语法错误则记为 `"RE"`。

给定 $K$ 个候选程序 $Y_K = (y_1, \dots, y_K)$，挑选器 $\mathcal{S}(Y_K)$ 按以下两步选出最终提交程序：
- **第一步（公开样例过滤，Public Filter）**：定义存活候选集合
  $$V(Y_K) = \begin{cases} \{i \in \{1,\dots,K\} : \text{Chk}(y_i) = 1\}, & \text{若 } \exists i \text{ 使得 } \text{Chk}(y_i) = 1, \\ \{1, \dots, K\}, & \text{若所有候选的 } \text{Chk}(y_i) = 0. \end{cases}$$
- **第二步（输出签名多数投票，Execution Signature Majority Vote）**：在存活集合 $V(Y_K)$ 内，将具有相同输出签名 $\sigma(y_i) = s$ 的程序归入同一个等价类簇 $C_s = \{i \in V(Y_K) : \sigma(y_i) = s\}$。挑选器选择**簇大小 $|C_s|$ 最大**的簇中的程序提交；若有多个最大簇并列（Tie），则在并列的最大簇之间均匀随机打破平局。

### 1.3 四大核心评测指标的定义

对每道测试题 $x$，我们在评测时独立采样 $N_{\text{eval}} = 16$ 个候选程序，并从中枚举无放回大小为 $K$（标准为 $K=8$）的子集，精确计算以下四个指标：
1. **`Pass@1`**：随机抽 1 个候选程序通过全部隐藏测试的概率 $\mathbb{E}_{y \sim \pi_\theta}[g(y)]$。
2. **`Pass@K`（Oracle Coverage）**：$K$ 个候选程序中至少有 1 个通过隐藏测试的概率 $\Pr(\exists i \in \{1,\dots,K\} : g(y_i) = 1)$。
3. **`Cov@K`（Filtered Oracle Coverage）**：$K$ 个候选中至少有 1 个**同时通过公开样例与隐藏测试**（即 $g(y_i)=1 \land \text{Chk}(y_i)=1$）的概率。这是任何遵循公开样例过滤的挑选器所能达到的**理论上限**。
4. **`Select@K`（核心主指标）**：挑选器 $\mathcal{S}(Y_K)$ 最终选出的那个程序通过全部隐藏测试的期望准确率：
   $$J_{\mathcal{S}}(\theta; K) = \mathbb{E}_{Y_K \sim \pi_\theta^K}\big[g(\mathcal{S}(Y_K))\big].$$
5. **`Gap@K`（挑选缺口）**：$\text{Gap@K} = \text{Cov@K} - \text{Select@K}$，衡量因为“假阳性错误程序结成多数派大簇压倒正确程序”而导致的精度损失。

### 1.4 为什么传统 RL 算法在 `Select@K` 下会失效？（核心矛盾）

在训练阶段，对每道题采样 $n = 16$ 个候选程序后，结合隐藏测试结果 $g_i \in \{0, 1\}$、公开检查器结果 $\text{Chk}_i \in \{0, 1\}$ 和输出签名 $\sigma_i$，全部候选天然划分为三类集合：
- **正确存活簇 $C = \{i : g_i = 1, \text{Chk}_i = 1\}$**：既通过公开样例又通过隐藏测试的真正正确解（由于题目为唯一输出题，正确解的签名全部相同）；
- **公开过滤淘汰集 $T = \{i : \text{Chk}_i = 0\}$**：连公开样例都未通过的候选（只要 $C \neq \emptyset$，它们就会在第一步被过滤掉，不会干扰投票）；
- **假阳性错误簇（False-Positive Wrong Clusters）$W_m = \{i : g_i = 0, \text{Chk}_i = 1, \sigma_i = s_m\}$**：**通过了简单的公开样例（$\text{Chk}_i = 1$），但在隐藏测试上错误的程序**。更致命的是，同一种错误逻辑（例如漏掉边界情况、贪心局部最优、整数溢出）往往会产生**完全相同的错误输出签名 $s_m$**，从而抱团形成大小为 $|W_m|$ 的错误簇。

只要某个假阳性错误簇的票数 $|W_m| \ge |C|$，多数投票挑选器 $\mathcal{S}$ 就会被假阳性错误簇劫持，即使模型已经生成了正确解（$|C| \ge 1$），最终选出的仍然是错误程序！传统 RL 方法在此暴露三大缺陷：
1. **仅用公开样例做奖励（`checker_reward`）**：对所有 $\text{Chk}_i = 1$ 的程序给予同等正奖励，导致更容易生成的假阳性错误解 $W_m$ 概率暴增，训练后期发生严重的**假阳性坍缩（Reward Hacking Collapse）**；
2. **优化 `Pass@1`（`drgrpo_pass1`）或 `Pass@K`（`pkpo_pass8`）的盲向性（Blind Direction）**：它们将所有错误候选（$g_i = 0$）一视同仁地赋予完全相同的负优势值，**无法区分“无害的 $\text{Chk}_i=0$ 错误 $T$”与“结党劫持投票的假阳性大簇 $W_m$”**。

### 2.2 数据集构建与 40K 上下文标定（Dataset Calibration）

数据源来自 `deepmind/code_contests` 竞赛编程题库：
1. **唯一输出过滤**：首先过滤掉交互题、多解题（需要 Special Judge 的题目）以及无有效 Python 3 解或测试输入不足的题目，保留 **692 道唯一标准输出竞赛题**。
2. **全量 `40,960` Context 零样本标定**：使用未训练的 `Qwen/Qwen3-4B` 在 `40,960` 上下文窗口下对全部 692 道题各采样 16 条轨迹，统计每道题的 `Pass@1`、`Cov@8`、`Select@8` 与 `Chk` 假阳性率。
3. **比赛级零重叠切分（`contest_id`-disjoint）**：严格按照比赛编号 `contest_id` 分组切分，确保 `train`、`dev`、`test` 三个集合之间**没有任何同一场比赛的题目重叠（`0` 比赛交集）**：
   - **训练集 `data/train.jsonl` / `data/train_active.jsonl`（91 题）**：由 80 道严格处于活跃学习区间（`0 < Pass@1 < 0.938` 且 `Cov@16 > 0`，既不恒满分也不恒零分）的题目 + 11 道高假阳性率（`Chk > 0`）难度攀升题组成。
   - **验证集 `data/dev.jsonl`（100 题）**：难度分布均衡的独立比赛验证集，供算法调优与检查点选择。
   - **隐藏测试集 `data/test.jsonl` + `data/test_hidden.enc`（100 题）**：独立比赛测试集，用于最终盲测。

#### 免训练理论诊断（Gate 1 闸门验证）
在 91 道活跃训练题上运行免训练诊断（`results/diag/summary.json`）与理论探针（`results/probe/probe_summary.json`），验证结果如下：
- **挑选器增益（`Select@8 - Pass@1`）**：**`+37.58` 个百分点**（从 `Pass@1 = 36.13%` 提升至 `Select@8 = 73.71%`）；
- **挑选缺口（`Cov@8 - Select@8`）**：**`2.87` 个百分点**（`Cov@8 = 76.58%` vs `Select@8 = 73.71%`）；
- **关键题比例（存在 $K$ 使得 $J_{\mathcal{S}}(K) < J_{\text{cov}}(K)$ 的题目占比）**：**`20.88%`**（超过五分之一的题目存在假阳性错误簇干扰多数投票）；
- **动态规划（DP）与 $\binom{16}{8} = 12,870$ 子集暴力枚举的最大绝对误差**：**`8.33e-15`**（机器精度级完全一致）；
- **盲向一阶泰勒展开验证**：当保持总覆盖率 $P = p_C + p_{W_1}$ 不变（因此 $\Delta J_{\text{cov}} = 0$，传统覆盖率 RL 梯度恒为 0），仅将 $\delta = 0.01$ 的概率质量从假阳性簇 $W_1$ 转移给正确簇 $C$ 时，实际 $\Delta J_{\mathcal{S}}$ 提升 `+0.77%`～`+0.99%`，一阶理论预测值与真实值比值为 **`1.018`**。

## 3. 对比方法与我们的方法详解（Methods & Mathematical Formulation）

所有训练方法均使用完全相同的 PPO/GRPO 裁剪代理损失框架与固定长度归一化（Dr. GRPO 的 $1/L_{\max}$ 长度无偏归一化，防止模型通过拉长或缩短废话来操纵梯度）：
$$\mathcal{L}(\theta) = \frac{1}{|B_{\text{active}}|} \sum_{x \in B_{\text{active}}} w_x \cdot \frac{1}{n} \sum_{i=1}^n \frac{1}{L_{\max}} \sum_{t=1}^{|y_i|} \Big[ -\min\big(r_{i,t}(\theta) A_i,\; \text{clip}(r_{i,t}(\theta), 1-\epsilon, 1+\epsilon) A_i\big) + \beta_{\text{KL}} D_{\text{KL}}^{\text{Schulman}}(\pi_\theta \| \pi_{\text{ref}})_{i,t} \Big]$$
其中 $r_{i,t}(\theta) = \frac{\pi_\theta(y_{i,t} \mid x, y_{i,<t})}{\pi_{\theta_{\text{old}}}(y_{i,t} \mid x, y_{i,<t})}$。**各个方法的唯一区别在于如何为每道题的 $n=16$ 个候选分配优势值 $A_i$、题目权重 $w_x$ 以及是否引入两轮执行反馈**：

### 3.1 基线 1：`frozen`（未训练基座模型）
- **设置**：直接评测原始 `Qwen/Qwen3-4B` 模型（`step_0000`），不进行任何强化学习微调。

### 3.2 基线 2：`checker_reward`（仅使用公开样例通过率奖励的 RL）
- **核心思想**：模拟没有隐藏测试集或仅用公开样例测试 $\text{Chk}(y_i) \in \{0, 1\}$ 作为奖励信号的强化学习。
- **优势函数公式**：
  $$A_i^{\text{chk}} = \text{Chk}_i - \frac{1}{n}\sum_{j=1}^n \text{Chk}_j, \qquad w_x = 1.$$
  若全组 $\text{Chk}_i$ 全为 0 或全为 1，则丢弃该题（`drop_problem = True`）。
- **实验目的**：验证理论命题 C（Proposition C）：当只奖励 $\text{Chk}_i = 1$ 时，策略会大量放大假阳性错误簇 $W_m$，在训练中后期导致 `Select@8` 甚至跌破未训练基座模型。按实验设计运行 `20` 步。

### 3.3 基线 3：`drgrpo_pass1`（标准 `Pass@1` Dr. GRPO 基线）
- **核心思想**：当前主流代码强化学习（如 DeepSeek-R1 / Dr. GRPO）的标准做法，直接以隐藏测试通过与否 $g_i \in \{0, 1\}$ 作为二值奖励，去除组标准差除以零导致的偏差，采用组均值中心化。这也是评测基准中提供给待测 Agent 的初始默认模板（`benchmark/agent_algorithm.py`）。
- **优势函数公式**：
  $$A_i^{\text{pass1}} = g_i - \frac{1}{n}\sum_{j=1}^n g_j, \qquad w_x = 1.$$
- **局限性**：完全忽略了测试时挑选器 $\mathcal{S}$ 的存在。无论是能通过公开过滤的正确解（$g_i=1, \text{Chk}_i=1$）还是会被公开过滤误杀的解（$g_i=1, \text{Chk}_i=0$），都拿到相同正奖励；无论是无害的 $\text{Chk}_i=0$ 错误解还是危险的假阳性合谋簇 $W_m$（$\text{Chk}_i=1, g_i=0$），都拿到完全相同的负奖励。

### 3.4 基线 4：`pkpo_pass8`（`Pass@8` 覆盖率无偏留一法优化 PKPO）
- **核心思想**：针对 `Pass@K`（$K=8$）覆盖率目标设计的无偏留一法（Leave-One-Out, LOO）策略梯度估计器。它奖励那些在 $K=8$ 子集中“雪中送炭”贡献覆盖率的正确样本。
- **优势函数公式**：记 $n=16$ 个样本中 $g_j = 1$ 的总数为 $c = \sum_{j=1}^n g_j$。若從不含样本 $i$ 的其余 $n-1$ 个样本中随机抽取 $K-1$ 个样本，其中**没有任何一个正确样本**的概率为超几何比率：
  $$\rho_i = \frac{\binom{(n-1) - c_{-i}}{K-1}}{\binom{n-1}{K-1}}, \quad \text{其中 } c_{-i} = c - g_i.$$
  候选 $i$ 对 `Pass@K` 的留一法边际贡献为 $r_i^{\text{pkpo}} = g_i \cdot \rho_i$，中心化后得到优势值：
  $$A_i^{\text{pkpo}} = r_i^{\text{pkpo}} - \frac{1}{n}\sum_{j=1}^n r_j^{\text{pkpo}}, \qquad w_x = 1.$$
- **局限性**：虽然考虑了 $K=8$ 的多样本覆盖率，但依然对挑选器 $\mathcal{S}$ 的多数投票机制“失明”（即所有 $g_i = 0$ 的样本都有 $r_i^{\text{pkpo}} = 0$，无法定向压制假阳性错误大簇 $W_m$）。

### 3.5 我们的方法 1：`sspo`（单轮挑选感知策略优化，Selection-Aware Policy Optimization）
- **核心思想**：直接将**测试时挑选器 $\mathcal{S}$ 在 $K=8$ 下的期望正确率**作为强化学习的优化目标！利用精确的动态规划（DP）算法，计算每个候选样本 $i$ 被加入大小为 $K$ 的子集时，对挑选器最终选出正确程序的**留一法边际贡献 $\Delta_i^{\mathcal{S}}$**，并与覆盖率优势进行凸组合，同时引入面向挑选缺口的题目级自适应权重 $w_x$。
- **数学构造与参数设置**：
  1. **挑选器留一法边际信用 $\Delta_i^{\mathcal{S}}$（精确 DP 计算）**：
     对任意样本 $i \in \{1, \dots, n\}$，从其余 $n-1$ 个样本中无放回抽取 $K-1$ 个组成子集 $S'$（共 $\binom{15}{7} = 6,435$ 种组合），比较“把样本 $i$ 放入子集后挑选器 $\mathcal{S}(S' \cup \{i\})$ 的胜率”与“$n$ 个样本整体 $K$-子集平均挑选器胜率 $\hat{J}_{\mathcal{S}}$”之差：
     $$\Delta_i^{\mathcal{S}} = \frac{1}{\binom{n-1}{K-1}} \sum_{\substack{S' \subseteq \{1,\dots,n\}\setminus\{i\} \\ |S'| = K-1}} u\big(S' \cup \{i\}\big) - \hat{J}_{\mathcal{S}},$$
     其中 $u(S)$ 为子集 $S$ 在挑选器 $\mathcal{S}$ 下选出 $g=1$ 程序的概率。通过分治多项式卷积 DP（`sspo/dp.py`），该留一法期望可在 $< 1\text{ ms}$ 内精确算出，且天然满足三项关键性质：
     - **组内零和性**：$\sum_{i=1}^n \Delta_i^{\mathcal{S}} = 0$；
     - **顺序性**：存活正确解的优势严格大于被过滤解，被过滤解严格大于假阳性错误解（$\Delta_C^{\mathcal{S}} > \Delta_T^{\mathcal{S}} > \Delta_{W_m}^{\mathcal{S}}$）；
     - **反合谋性（Anti-Collusion）**：假阳性错误簇 $W_m$ 越大（越容易在多数投票中击败正确解），其成员收到的负惩罚 $\Delta_{W_m}^{\mathcal{S}}$ 就越重！
  2. **混合优势函数（$\alpha = 0.7$）**：
     为了在正确率极低时保持稳定的覆盖率探索信号，将覆盖率留一法优势 $A_i^{\text{cov}}$（基于 $\tilde{g}_i = \mathbf{1}[g_i=1 \land \text{Chk}_i=1]$ 的 `Cov@8` 留一法优势）与挑选器边际优势 $\Delta_i^{\mathcal{S}}$ 按锁定超参数 $\alpha = 0.7$ 加权：
     $$A_i^{\text{sspo}} = (1 - \alpha) A_i^{\text{cov}} + \alpha \Delta_i^{\mathcal{S}}, \qquad (\alpha = 0.7).$$
  3. **题目级自适应聚焦权重 $w_x$**：
     $$w_x = \text{clip}\Big(\hat{J}_{\text{cov}}(1 - \hat{J}_{\text{cov}}) + \big(\hat{J}_{\text{cov}} - \hat{J}_{\mathcal{S}}\big),\; 0.05,\; 1.0\Big).$$
     当一道题处于高方差学习区（$\hat{J}_{\text{cov}} \approx 0.5$）或存在较大挑选缺口（$\hat{J}_{\text{cov}} - \hat{J}_{\mathcal{S}} > 0$，即正确解被假阳性簇压制）时，赋予更高的梯度权重。

### 3.6 我们的方法 2：`sspo_turns2`（两轮公开样例执行反馈 + SSPO）
- **核心思想**：将测试时与训练时的公开样例检查器 $\text{Chk}(y)$ 从单纯的“事后过滤器”升级为**两轮交互式修正回路（2-Turn Execution-Guided Revision）**，并使用上述 `SSPO`（$\alpha = 0.7$）对最终轨迹进行挑选感知策略优化。
- **两轮生成与训练流程**：
  - **第一轮（Turn 1）**：模型针对题目 $x$ 生成初稿程序 $y^{(1)}$，立即在公开样例上执行得到 $\text{Chk}(y^{(1)})$ 及具体失败诊断信息（如 `WrongAnswer` 的期望输出 vs 实际输出、`TimeLimitExceeded` 或 `RuntimeError` 报错信息）。
  - **第二轮（Turn 2）**：
    - 若第一轮已通过全部公开样例（$\text{Chk}(y^{(1)}) = 1$），则直接采纳 $y^{(1)}$ 作为最终候选，无需第二轮生成；
    - 若第一轮未通过公开样例（$\text{Chk}(y^{(1)}) = 0$），则将第一轮代码与公开样例报错反馈拼接成修正提示（Revision Prompt），让当前策略生成修正后的代码 $y^{(2)}$，并以最终代码参与后续挑选器 $\mathcal{S}$ 和 `SSPO` 策略梯度更新。

#### 深度归因：为什么 `checker_reward` 和 `pkpo_pass8` 会在训练后期退化，而 `sspo` 不会？
1. **`checker_reward` 的假阳性合谋机制**：
   在训练前 15 步，奖励 $\text{Chk}(y)=1$ 帮助模型减少了语法错误与明显偏题的输出，使得 `Select@8` 一度上升到 `40.05%`。但到了第 15～20 步，模型发现对于复杂题目，写出“直接特判样例或使用简单贪心骗过公开样例”的假阳性程序比写出真正正确的算法容易得多。这导致假阳性错误簇 $W_m$ 急剧膨胀（簇不纯率飙升至 `11.00%`，挑选缺口 `Gap@8` 扩大到 `1.87%`），在第 20 步测试集 `Select@8` 暴跌 `2.39 pt` 至 `37.66%`，验证集跌至 `31.30%`，双双低于未训练基座！
2. **`pkpo_pass8` 的后期退化**：
   `pkpo_pass8` 只关心“16 个采样里有没有至少 1 个正确解”，当某道题已经能稳定生成 1～2 个正确解时，$\rho_i$ 权重迅速衰减；同时它对假阳性错误簇 $W_m$ 与普通错误 $T$ 给出一模一样的零奖励，无法阻止假阳性错误解在其余采样槽位中聚集。因此在第 20 步之后，其测试集 `Select@8` 从 `39.91%` 下滑至 `38.24%`，验证集从 `33.28%` 下滑至 `31.10%`。
3. **`sspo` 的反合谋自愈机制**：
   在 `sspo` 中，一旦某个假阳性错误签名 $s_m$ 在 16 个采样中出现多次（$|W_m| \ge 2$），DP 留一法算出的边际贡献 $\Delta_i^{\mathcal{S}}$ 会对 $W_m$ 中的每一个样本施加**成倍放大的负梯度惩罚**，同时对正确簇 $C$ 施加高额正激励。这种精确针对多数投票边界的信用分配，使得 `sspo` 在训练中后期（第 20～30 步）始终在测试集和验证集上保持正向增益。

## 5. 总结与对评测基准（SSPO-Bench）的启示

1. **基准区分度与有效预算验证**：
   在单机 24 小时训练-评测预算内（30 步 RL 训练 + 验证/测试集评测），各算法从同一个 `38.64%` 的 `Qwen/Qwen3-4B` 基座出发，展现出清晰的梯度分化：
   $$\text{checker\_reward } (37.66\%) < \text{pkpo\_pass8 } (38.24\%) < \text{frozen } (38.64\%) < \text{drgrpo\_pass1 } (38.79\%) < \textbf{sspo } (\mathbf{39.44\%\text{ final} / 40.11\%\text{ best}}) < \textbf{sspo\_turns2 } (\mathbf{43.22\%}).$$
2. **评测 Agent 的挑战空间**：
